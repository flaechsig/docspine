---
id: ADR-0016
title: Update mit spine-update, Version nur in den ausgelieferten Dateien
status: proposed
date: 2026-10-04
---

## Kontext

Ein Update ist derselbe Einzeiler wie die Installation. Danach war bisher `spine-init`
aufzurufen, das dafür einen eigenen Abschnitt hatte. Das passt nicht: Das Projekt gibt es
dann schon, „init“ ist der falsche Name.

Die installierte Version stand an drei Stellen: im Kopf von `STANDARD.md`, im Kopf des
README und als Feld `docspine:` im Profil. Das Profilfeld musste nach jedem Update von Hand
nachgezogen werden, obwohl `STANDARD.md` bei jedem Update ohnehin neu kommt.

Ein Update kann Dateien hinterlassen, die docspine nicht mehr ausliefert (beobachtet im
Probelauf: `docs/STANDARD.md` nach ADR-0015).

## Entscheidung

- **Eigener Skill `spine-update`,** nach jedem Update aufzurufen, ohne Fallunterscheidung.
  Er übersetzt das README neu, wo die englische Quelle eine andere Version hat, räumt
  Dateien aus älteren Versionen auf und prüft. Gibt es nichts zu tun, sagt er das.
  `spine-init` ist nur noch Einrichtung.
- **Die Version steht nur in den ausgelieferten Dateien:** im Kopf von `STANDARD.md`
  (installiert) und im Kopf des README (übersetzt aus). Das Profil trägt keine Version.
- **Fehlerklasse 14** vergleicht README mit installiertem Standard (REQ-0027, löst
  REQ-0017 und REQ-0026 ab).
- **Die README-Quelle liegt in `.docspine/README.en.md`,** weil `spine-init` und
  `spine-update` sie brauchen.
- **`.docspine/MANIFEST`** listet die ausgelieferten Dateien. `spine-update` erkennt daran
  Skills und Dateien, die docspine nicht mehr liefert.

## Konsequenzen

- Nach einem Update muss niemand etwas von Hand nachtragen.
- Quickstart: „dieselbe Zeile erneut ausführen, danach `/spine-update`“.
- Ob ein Update eine neue Übersetzung braucht, hängt an der Versionsnummer. Sie muss also
  steigen, wenn sich die README-Quelle ändert. Wann genau die Version steigt, ist noch
  festzulegen.
