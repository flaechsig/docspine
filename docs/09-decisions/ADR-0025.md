## Kontext

Von einer neuen Version erfährt man heute nur, wenn man selbst nachsieht (US-0018).
Die installierte Version steht in der ersten Zeile von `.docspine/STANDARD.md`. Die
neueste Version und ihre Änderungen stehen im Changelog des Zweigs `dist`, aus dem die
Installation liest. Offen war, wann und wie geprüft wird. Die Prüfung braucht Netz und
darf eine Arbeit ohne Netz nicht stören.

## Entscheidung

- Das Prüfwerkzeug bekommt den Befehl `version`. Er liest den Changelog aus `dist` und
  meldet die installierte und die neueste Version. Ist eine neuere da, zeigt er die
  Einträge dazwischen.
- Er fragt höchstens einmal am Tag im Netz nach. Das Ergebnis liegt im Cache-Ordner des
  Nutzers, nicht im Projekt. `--now` fragt sofort nach.
- Ohne Netz meldet er nach höchstens 5 Sekunden, dass er nicht prüfen konnte, zeigt das
  letzte Ergebnis aus dem Cache und endet ohne Fehler.
- Die Skills, mit denen man arbeitet (`spine-require`, `-impact`, `-decide`, `-build`,
  `-prove`, `-gate`), rufen den Befehl zu Beginn auf. Ist eine neuere Version da, nennen
  sie sie mit der Release-Note und bieten an, sie einzuspielen: auf einem eigenen Branch
  die Installation ausführen, danach `spine-update`. Das geschieht nur nach Rückfrage,
  weil Dateien von außen geholt werden. `spine-init`, `spine-adopt` und `spine-update`
  laufen direkt nach einer Installation und prüfen deshalb nicht.

Verworfen:
- **Nur der Befehl, ohne Skills:** Man müsste selbst daran denken. Das ist der heutige
  Zustand.
- **Hook beim Sitzungsstart in Claude Code:** gilt nur für ein Werkzeug, und docspine
  müsste dafür `.claude/settings.json` ins Projekt schreiben (ADR-0009).
- **Die Prüfung (`check`) meldet es:** Die Prüfung muss ohne Netz und immer gleich
  ablaufen. Im Build würde eine neue Version plötzlich als Meldung auftauchen.
- **Zeitpunkt im Projekt merken:** Jede Prüfung würde eine Datei ändern, die in
  `git status` auftaucht.

## Konsequenzen

- Wer mit den Skills arbeitet, erfährt spätestens einen Tag nach einem Release davon.
- Ohne Skills bleibt der Befehl `version`. Er funktioniert mit jedem Werkzeug.
- Der Befehl braucht Zugriff auf `raw.githubusercontent.com`. Er schickt nichts mit
  außer dem Abruf selbst.
