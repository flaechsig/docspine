id: ADR-0013
title: Testergebnisse als Schnittstelle, keine Module
status: proposed
date: 2026-10-03
---

## Kontext

ADR-0006 sah sechs optionale Module vor, darunter `trace-junit5`. Damit hinge docspine
an Java, JUnit und Maven. Ziel ist aber ein Standard ohne Bindung an eine Technik.

Der naheliegende neutrale Weg, die CLI liest die Testberichte im JUnit-XML-Format,
trägt nicht. Prüfung am 2026-10-03 am Ursprungsprojekt (125 Surefire-Berichte): Die Berichte
enthalten keine Tags. `ProtocolInvocationServiceTest` trägt `@Tag("REQ-0014")` und
`@Tag("REQ-0047")`, im XML kommt keine `REQ-`-Zeichenkette vor. Ein `<testcase>`
enthält nur `name`, `classname` und `time`.

Der heutige Listener im Ursprungsprojekt liefert dagegen genau das
Nötige: je Modul eine `req-coverage.json` mit REQ-ID und Ergebnis.

Von den übrigen Modulen enthalten nur `legacy` echte prüfbare Regeln. `devlog`,
`guides` und `runbooks` beschreiben nur Ordner, `git-workflow` regelt den
Repository-Ablauf und nicht die Doku.

## Entscheidung

### Testergebnisse

docspine legt nur ein **Ergebnisformat** fest. Wie ein Projekt es erzeugt, ist seine
Sache:

```json
{ "results": [ { "req": "REQ-0014", "result": "passed", "test": "ProtocolInvocationServiceTest" } ] }
```

- Dateiname `req-results.json`, beliebig viele im Repo. Die CLI liest alle.
- Das Ursprungsprojekt und blocpress behalten ihren Listener als Teil des Projekts und passen nur
  das Format an.
- docspine liefert keinen Adapter-Code. Ein JUnit-5-Listener wird als **Beispiel**
  dokumentiert.
- Projekte ohne Tests belegen über `evidence` und `verification`.

Verworfen:
- **REQ-ID im Testnamen:** neutral, aber 99 Tags im Ursprungsprojekt umbauen, Tags auf
  Klassenebene gehen verloren.
- **CLI liest Quelltext und Bericht:** keine Änderung an Tests, aber eine Heuristik
  (verschachtelte Klassen, parametrisierte Tests) und je Sprache ein eigenes Muster.

### Keine Module

- `trace-junit5` entfällt, ersetzt durch das Ergebnisformat im Kern.
- `devlog`, `guides`, `runbooks` entfallen. Projekteigene Ordner neben den Kapiteln
  sind erlaubt und brauchen keine Regeln.
- `git-workflow` entfällt. Branch-Regeln sind Projektregeln in `AGENTS.md`.
- `legacy` wird ein Abschnitt im Kern, der nur gilt, wenn `docs/legacy/` existiert.

## Konsequenzen

- docspine hat keine Bindung an eine Technik. Einzige Voraussetzung ist die CLI selbst.
- `PROFILE.md` verliert das Feld `modules`.
- Ein Standard für alle, `STANDARD.md` wird nicht mehr nach Modulen gefiltert.
- Wer Testergebnisse nutzen will, braucht eine kleine Anbindung im eigenen Projekt.
