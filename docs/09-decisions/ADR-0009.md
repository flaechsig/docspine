id: ADR-0009
title: Steuernde Artefakte und die Grenze zu KI-Werkzeugen
status: proposed

## Kontext

Die Doku soll von jeder KI und jedem Menschen aufgegriffen werden können, nicht nur
von Claude Code. Heute liegt Wissen teilweise nur in Claude-spezifischen Dateien:

- Die zwölf Skills im Ursprungsprojekt (1638 Zeilen) enthalten Regeln, die nirgends sonst
  stehen, z. B. den Katalog der EARS-Muster und die Status-Wahl für neue
  Anforderungen.
- `CLAUDE.md` und `AGENTS.md` überschneiden sich. `AGENTS.md` ist im Ursprungsprojekt von
  einem anderen Werkzeug (GSD) erzeugt.

Skills sind seit Dezember 2025 ein offener Standard (Agent Skills, `SKILL.md`), den
neben Claude Code u. a. Codex, Copilot, Cursor und Gemini CLI unterstützen. Als
werkzeugübergreifender Ort setzt sich `.agents/skills/` durch. `AGENTS.md` im Root
ist der werkzeugübergreifende Einstieg für KI-Agenten.

Test am 2026-10-03 mit Claude Code 2.1.288 in einem Wegwerf-Repo: Claude Code findet
Skills in `.agents/skills/` nicht von selbst, wohl aber über einen symbolischen Link
`.claude/skills → ../.agents/skills`.

## Entscheidung

**Grenze:** Alles, was man wissen muss, liegt als normale Datei im Repo. Werkzeug-
spezifisch ist nur, wie bequem man es aufruft. Probe: Wird `.claude/` gelöscht, geht
keine Regel verloren.

```
<projekt>/
  AGENTS.md                 neutral   Einstieg für jede KI: Gate-Befehl, Wege durch
                                      die Doku, Verweis auf STANDARD.md
  docs/STANDARD.md          neutral   die Regeln (Kopie aus docspine, ADR-0004)
  docs/PROFILE.md           neutral   die Projektwerte (ADR-0006)
  .agents/skills/           neutral   Abläufe nach Agent-Skills-Standard (ADR-0010)
  .claude/
    CLAUDE.md               Claude    „@../AGENTS.md“ + Claude-Eigenheiten
    skills → ../.agents/skills        symbolischer Link
```

- **Steuernde Artefakte** sind `AGENTS.md`, `STANDARD.md` und `PROFILE.md`.
- **Wissen steht im Standard, Abläufe im Skill.** Ein Skill sagt, was in welcher
  Reihenfolge zu fragen und zu tun ist, und verweist für die Regeln auf Abschnitte in
  `STANDARD.md`.
- **Skills nutzen nur Felder des offenen Standards** im Frontmatter und nennen im
  Text keine werkzeugspezifischen Tool-Namen.
- **`AGENTS.md` enthält keine Architekturinhalte**, nur Verweise in das Dokument.
- **Das Frontmatter-Schema wird zusätzlich als JSON Schema** veröffentlicht, damit
  Editoren und andere Werkzeuge es prüfen können.

## Konsequenzen

- Eine andere KI braucht nur Repo und Gate. Claude bekommt mit den Skills geführte
  Abläufe, aber kein zusätzliches Wissen.
- Die Skill-Inhalte aus dem Ursprungsprojekt und blocpress müssen aufgeteilt werden: Regeln nach
  `STANDARD.md`, Abläufe in die neuen Skills.
- Inhalte von Fremdwerkzeugen (z. B. GSD) in `AGENTS.md` müssen heraus oder in einen
  klar abgegrenzten Abschnitt.
- Unter Windows braucht der symbolische Link `core.symlinks=true`. Liest Claude Code
  `.agents/skills/` künftig selbst, entfällt der Link.
- Prüfbar über einen Kaltstart-Test: Ein Agent ohne Skills bekommt nur das Repo und
  eine Aufgabe. Schafft er sie, ist die Doku portabel.
