Als **Projektverantwortlicher** möchte ich ein bestehendes Projekt mit Code und Doku in den Standard überführen lassen, damit die Migration geführt und nicht von Hand geschieht.

**Hintergrund.** Weg für die Migration der drei Projekte (ADR-0010).

**Erfahrungen aus der Migration von blocpress (2026-10-05),** als Grundlage für den Skill:
1. Projektfremdes aus `docs/` herauslösen (dort: die Website, die GitHub Pages aus `docs/`
   veröffentlichte, nach `site/` mit eigenem Workflow), Pfade in Tests und Workflows
   nachziehen.
2. Installieren; vorhandene `.claude/skills/` vorher auflösen: Methodik-Skills entfallen,
   projekteigene nach `.agents/skills/`.
3. Inhalte umziehen (`git mv`, damit die History bleibt): Spec nach `01-goals/`, ADRs von
   AsciiDoc in Markdown mit vierstelligen Nummern, arc42-Kapitel mit Inhalt in
   Kapiteldateien, Altbestand und alte ROADMAP nach `docs/legacy/`, generierte Ansichten
   und `CONVENTIONS.md` löschen.
4. Schema angleichen: Epic-IDs in Großbuchstaben, `obligation` englisch, Epic-Status und
   `confidence` raus, `evidence` nur Umsetzung, Verweise auf neue Pfade und IDs.
5. Vision: Kernsatz aus vorhandenem Text, Abschnitt „Themen“.
6. Profil (Normquellen aus den Requirements), `AGENTS.md`, `CLAUDE.md` mit Verweis.
7. Tests: `@Tag` → `@DisplayName`, parametrisierte Tests mit `{displayName}`.
8. Build: eigenes Gate ersetzen, im Reactor als letztes Modul; CI anpassen.
9. Prüfen ohne Tests, dann der volle Build wie in der CI.
